# 문제 정의: 외부에 닫힌 상태 관리 도구들

## XState와 useReducer가 잘 안 쓰이는 이유

### 핵심 문제: 외부에 닫혀 있다

XState와 useReducer는 상태 모델링에 강력한 도구다. 선언적으로 상태를 표현하고, 구현과 인터페이스를 분리할 수 있다. 그런데도 실제로는 잘 안 쓰인다.

이유는 **외부 상태에 닫혀 있기 때문**이다.

"외부에 닫혀 있다"는 것은 이런 의미다:
- 외부 상황을 무시하고 자신의 내부 상태만 철저히 관리한다
- 오직 이벤트를 통해서만 소통하려 한다

### React 생태계와의 충돌

React 컴포넌트 생태계에서 가장 강력한 힘을 가진 것은 **props로 전달되는 외부 상태**다.

하지만 reducer나 XState는 이 외부 상태를 다루기 까다롭다. 외부에서 주입되는 상태 변화에 유연하게 반응하기 어려운 구조이기 때문이다.

### 그래서 언제 쓸 수 있나?

XState나 useReducer가 제 기능을 발휘할 수 있는 곳은 한정적이다:

> 외부 상태에 영향받지 않는, 기능의 최상위 루트 컴포넌트

즉, 스스로 상태의 주인이 될 수 있는 곳에서만 효과적이다.

### 아까운 유산

그럼에도 XState의 상태 차트(Statechart) 개념 자체는 매우 유용하다:
- 복잡한 상태 전이를 시각화
- 불가능한 상태를 원천 차단
- 상태 로직을 명확하게 표현

하지만 "외부에 닫혀 있다"는 구조적 한계 때문에 실무에서 채택되지 못하고, 결국 이 귀중한 개념들이 개발자들에게 습득되지 못한 채 버려지고 있다.

**도구의 한계가 개념의 가치까지 묻어버리는 셈이다.**

## 동기화 문제의 본질

### 외부 상태와 내부 머신 사이의 간극

```
┌─────────────────┐         ┌─────────────────┐
│  외부 상태        │  ──?──▶ │      내부 머신     │
│  (props)        │         │  (uncontrolled) │
│                 │ ◀──?─── │                 │
└─────────────────┘         └─────────────────┘
```

1. **외부 → 내부**: 어떤 이벤트를 보내야 하나?
2. **내부 → 외부**: 어떻게 동기화해야 하나?
3. **충돌 시**: 누가 우선인가?

### 구체적인 문제 상황들

#### 1. 외부 상태 변화 → 이벤트 매핑

```typescript
// props.isOpen이 true → false로 바뀌었을 때
// 어떤 이벤트를 보내야 하나?

// 단순 매핑?
isOpen: true → 'OPEN'
isOpen: false → 'CLOSE'

// 하지만 현재 머신 상태에 따라 달라질 수 있음
// 'loading' 상태에서 isOpen: false가 오면?
// - CLOSE 보내도 되나?
// - 무시해야 하나?
// - CANCEL 먼저 보내야 하나?
```

#### 2. 내부 상태 변화 → 외부 알림

```typescript
// 머신이 'closed' 상태가 되면
// props.onOpenChange(false) 호출해야 하나?

// 하지만 이미 외부가 isOpen: false를 보내서 닫힌 거라면?
// 중복 호출? 무한 루프?
```

#### 3. 동기화 타이밍

```typescript
// 외부: isOpen: false
// 내부: state: 'open', isClosing: true (애니메이션 중)

// 누가 맞는 상태?
// 애니메이션 끝날 때까지 기다려야 하나?
```

## 해결해야 할 핵심 과제

> 외부 상태(props)와 내부 상태(XState/reducer)를
> 어떻게 안전하게 동기화할 것인가?

이걸 **선언적으로 정의**할 수 있는 인터페이스가 필요하다.
